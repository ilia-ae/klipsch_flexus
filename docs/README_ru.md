Кастомная интеграция Home Assistant для саундбаров **Klipsch Flexus** — управление через **локальный HTTP API**, без облака, без задержек.

> ✅ **41 сущность**. Все команды записи проверены вживую на прошивке 2026 (HMAC-подпись) и работают в standby. Каждый коммит в `main` сначала проходит тесты локально: см. [Результаты тестов](#результаты-тестов).

## 📸 Панель (Dashboard)

Кастомная Lovelace-панель целиком на сущностях интеграции — вход, звуковой режим, ночной/диалог, EQ-пресеты, фильтр Dirac, тон (bass/mid/treble), уровни surround-каналов и сабвуферы — всё вживую по локальному API.

### Поддерживаемые модели

| Модель | Каналы | Особенности |
|--------|--------|-------------|
| **Flexus CORE 300** | 5.1.2 | Dirac Live, Dolby Atmos, 13 драйверов |
| **Flexus CORE 200** | 3.1.2 | Dolby Atmos up-firing |
| **Flexus CORE 100** | 2.1 | Virtual Dolby Atmos |

Интеграция не проверяет модель. Она добавляет любой саундбар Flexus, который объявляет себя через Google Cast, и для всех моделей использует один и тот же локальный API и одинаковый набор из 41 сущности. Мейнтейнер тестирует на CORE 300. Управление тем, чего нет в вашей модели (например, верхними каналами на CORE 100), может завершиться ошибкой.

> Саундбар нужно **сначала полностью настроить в официальном приложении Klipsch Connect Plus** — пройдите весь онбординг хотя бы один раз (Wi-Fi, обновление прошивки, подключение колонок, калибровка Dirac). На прошивке 2026 года именно это создаёт учётные данные для подписи команд, поэтому при незавершённой настройке большинство команд останутся без авторизации. Интеграция отвечает только за текущее управление.

## ⚠️ Совместимость с прошивкой (обновление 2026)

Обновление прошивки 2026 года (**Device Version `1.1.3.x`**, например `1.1.3.0x7cd294e`, Cast-сборка `20250512_0201_RC25`) изменило локальный HTTP API двумя способами:

1. **`setData` теперь требует `POST` с JSON-телом.** Старый `GET /api/setData?...` возвращает `405 Strict HTTP required!`. **Исправлено в v2.4.1** — обновите интеграцию.
2. **Большинство записей `setData` теперь требуют авторизации** (`settings:/webserver/authMode = setData`). Защищённые команды отвечают `401 Forbidden` с заголовком `WWW-Authenticate: HMAC_SHA256_AES256`. **Исправлено в v2.5.0** — интеграция теперь подписывает такие записи автоматически.

### Что работает на новой прошивке

| Возможность | Статус |
|-------------|--------|
| Все сенсоры / чтение статуса (`getData`) | ✅ Работает |
| Громкость, без звука (Mute) | ✅ Работает |
| Вход, звуковой режим, ночной/диалог, бас/средние/высокие, пресет EQ, Dirac, сабвуфер и surround-уровни, питание | ✅ Работает (подпись HMAC, v2.5.0+) |
| LED, lip-sync, баланс, Loudness, DND, авто-standby + ещё 4 переключателя | ✅ Работает (с подписью; добавлено в v2.5.8–2.5.9) — в том числе в standby |

Текущий статус по каждой команде виден в **Download diagnostics** (раздел `command_health`, добавлен в v2.4.2). Он только читает: для каждой команды показывает, читается ли настройка и как устройство ответило на записи с последней загрузки интеграции (`http_status`, `needs_auth` — если устройство потребовало подпись).

### Статус исправления

✅ **Решено в v2.5.0 — полное управление восстановлено, действий от пользователя не требуется.** Подпись запросов `HMAC_SHA256_AES256` реализована. Учётные данные устройства выводятся автоматически из MAC-адреса саундбара (который интеграция и так определяет), поэтому **настраивать ничего не нужно** — просто обновите интеграцию. Начиная с **v2.5.9** MAC считывается детерминированно с самого устройства (`settings:/system/primaryMacAddress`), поэтому определение срабатывает с первого раза на любом экземпляре (прежний поиск через реестр/ARP оставлен как запасной вариант). Подписанные записи уходят на HTTPS-эндпоинт устройства; громкость/Mute продолжают работать без подписи.

> Требуется пакет `cryptography` (поставляется вместе с Home Assistant, поэтому уже присутствует; в требованиях манифеста не указан).

📖 **Как мы это вскрывали** — вся история расследования (blutter, Frida, WireGuard-MITM, разбор «security-театра»): [рапорт](REPORT.md) (есть и [на английском](REPORT_en.md)).

Старые прошивки (до `1.1.3`) не затронуты и сохраняют полное управление через устаревший `GET`-fallback.

## Возможности

### Медиаплеер
- **Громкость** — уровень, шаг вверх/вниз, выключение звука
- **Питание** — включение / выключение (сетевой режим ожидания)
- **Источник сигнала** — TV ARC, HDMI, SPDIF, Bluetooth, Google Cast. Когда активно стриминговое приложение (Spotify Connect, TIDAL Connect, QPlay), USB или калибровка Dirac, источник показывает это
- **Режим звука** — Movie, Music, Game, Sport, Night, Direct, Surround, Stereo
- **Воспроизведение** — play/pause, следующий/предыдущий трек
- **Медиа-данные** — название, артист, альбом, обложка, приложение-источник

### Уровни каналов (11 слайдеров: 9 от -6 до +6 дБ, 2 сабвуфера от -12 до +6 дБ)

| Канал | Описание |
|-------|----------|
| Front Height | Верхний фронтальный (Dolby Atmos) |
| Back Height | Верхний тыловой (Dolby Atmos) |
| Side Left / Right | Боковые окружающие колонки |
| Back Left / Right | Тыловые окружающие колонки |
| Subwoofer Wireless 1 / 2 | Уровни сабвуферов (от -12 до +6 дБ) |
| Bass / Mid / Treble | Тембр: НЧ / СЧ / ВЧ |

### Настройки звука (Select)
- **EQ Preset** — Flat, Bass, Rock, Vocal (+ Custom — устройство сообщает его, как только изменены Bass / Mid / Treble (из HA или приложения Klipsch) или в приложении задана своя кривая; выбрать его из HA нельзя)
- **Ночной режим** — снижает динамический диапазон для тихого прослушивания
- **Режим диалога** — усиливает речь (3 уровня)
- **Dirac Live** — коррекция помещения (фильтры считываются с устройства)
- **Яркость LED** — передний светодиод: Off / Dim / Bright
- **Таймаут простоя** — время простоя до авто-перехода в standby: Выкл / 5 / 10 / 15 / 30 мин

### Настройки (Number)
- **Задержка lip-sync** — ручная синхронизация A/V (0–500 мс)
- **Баланс** — лево/право (−10…+10 дБ)

### Переключатели (Switch)
- **Авто lip-sync** — автоматическая задержка A/V
- **Обход EQ** — отключение эквалайзера
- **Авто-питание** — автоматическое поведение вкл/standby
- **Loudness** — компенсация громкости на низком уровне
- **Не беспокоить** — подавление уведомлений/звуков
- **Авто-standby** — переход в режим ожидания при простое
- **Звуки интерфейса**, **Доп. звуковые режимы**, **Авто-сопряжение BLE-пульта**, **Авто-обновление прошивки**

> Все перечисленные выше настройки можно записывать и когда саундбар в **режиме ожидания** (устройство применяет и сохраняет их); интеграция держит сущности доступными и запоминает заданное значение, а не откатывает его.

### Диагностика
- **Время отклика** — длительность опроса API в мс, счётчики запросов/ошибок
- **Статус устройства** — Вкл / Ожидание / Оффлайн с информацией о декодере, входе, режиме
- **MAC для подписи** — MAC, которым подписываются записи на прошивке 2026 (схема, кандидаты, разрешённое состояние)
- **Сетевое подключение** — активный проводной/беспроводной интерфейс, имена интерфейсов, источники MAC
- **Режим работы** / **Тест колонок** — состояние устройства только для чтения (отображается, намеренно без управления)
- **Задержки колонок** (проводной/беспроводной саб, беспроводной surround) — только для чтения, авто-калибровка устройством
- **Скачать диагностику** — полный дамп состояния (Настройки > Устройства > Klipsch Flexus > Скачать диагностику). IP-адрес, все MAC-адреса, BSSID Wi-Fi, ID устройства и URL потоков в нём скрыты

### Переводы
Полный перевод интерфейса на **7 языков**: английский, русский, немецкий, испанский, французский, итальянский, португальский. Все имена сущностей, состояния и экраны настройки переведены.

## Установка

### HACS (рекомендуется)

Klipsch Flexus есть в стандартном каталоге HACS, поэтому добавлять пользовательский репозиторий не нужно.

[![Открыть этот репозиторий в HACS вашего Home Assistant.](https://my.home-assistant.io/badges/hacs_repository.svg)](https://my.home-assistant.io/redirect/hacs_repository/?owner=ilia-ae&repository=klipsch_flexus&category=integration)

1. Нажмите кнопку выше, чтобы открыть Klipsch Flexus в вашем HACS (ссылка My Home Assistant), или откройте **HACS** и найдите **Klipsch Flexus**
2. Нажмите **Скачать** и перезапустите Home Assistant
3. Саундбар должен **обнаружиться автоматически** — проверьте уведомления
4. Или перейдите в **Настройки** > Устройства и службы > **Добавить интеграцию** > Klipsch Flexus

### Вручную

1. Скопируйте `custom_components/klipsch_flexus/` в директорию `config/custom_components/` вашего HA
2. Перезапустите Home Assistant
3. Добавьте интеграцию через Настройки > Устройства и службы

### Обновление

После обновления интеграции (через HACS или вручную) **перезапустите Home Assistant**: HA загружает Python-код интеграции при старте, поэтому новая версия заработает только после перезапуска. Изменение **опций** или **перенастройка** хоста применяются сразу, без перезапуска (запись перезагружается).

### Бета-версии

Новые функции и исправления сначала выходят как **бета**: pre-release на GitHub с тегом `vX.Y.Z-beta.N`. Стабильный релиз `vX.Y.Z` выходит позже. HACS предлагает бету только тем, кто её включил. Если ничего не делать, вы остаётесь на стабильных релизах и не получаете уведомлений о бетах.

Как получать беты (HACS 2.x; названия приведены на английском, ваш HACS может показывать их в переводе):

1. Откройте **Настройки** > Устройства и службы > **HACS** и запись службы **Klipsch Flexus** (HACS создаёт такую запись для каждого скачанного репозитория)
2. Найдите переключатель **Pre-release** (диагностическая сущность). По умолчанию он отключён: откройте его, нажмите значок шестерёнки, включите сущность и сохраните
3. Включите **Pre-release**. Теперь HACS предложит свежую бету как обновление. Чтобы проверить сразу, откройте Klipsch Flexus в HACS и выберите **Update information** в меню ⋮
4. Установите обновление и перезапустите Home Assistant

Чтобы вернуться на стабильную версию, выключите **Pre-release**. HACS снова будет предлагать только стабильные релизы, а бета останется у вас, пока её не заменит следующий стабильный релиз. Чтобы вернуться сразу, откройте Klipsch Flexus в HACS, выберите ⋮ > **Redownload** > **Need a different version?**, выберите самый новый релиз без пометки *pre-release*, скачайте его и перезапустите Home Assistant.

## Автообнаружение

Саундбар автоматически обнаруживается в сети через **mDNS / Zeroconf** (протокол Google Cast).

При включённом саундбаре Home Assistant покажет уведомление:
> Найден **Klipsch Flexus CORE 300** по адресу `192.168.1.100`. Добавить этот саундбар?

**Как это работает:**
- Саундбар анонсирует себя как `Flexus-Core-*` через сервис `_googlecast._tcp` mDNS
- Интеграция определяет устройство по TXT-записям `md` (модель) и `fn` (имя)
- Прокси AirCast автоматически отфильтровываются

Если автообнаружение не работает (например, сетевая изоляция), вы всегда можете добавить интеграцию вручную, указав IP-адрес.

## Как это работает

Саундбар предоставляет локальный HTTP API на порту 80:
- `GET /api/getData` — чтение параметров
- `POST /api/setData` — запись параметров (JSON body; для старых прошивок — fallback на GET)
- `GET /api/getRows` — списки данных (фильтры Dirac)

На прошивке 2026 команды записи с HMAC-подписью идут вместо этого на `POST https://<IP>/api/setData`.

### Устойчивая работа с медленным устройством

Klipsch Flexus имеет **однопоточный HTTP-сервер**, обрабатывающий один запрос за раз. Интеграция учитывает это ограничение:

| Механизм | Описание |
|----------|----------|
| Сериализация запросов | Все вызовы API проходят через `asyncio.Lock` — без параллелизма |
| Повторы с задержкой | Записи (кроме управления воспроизведением) и запрос питания повторяются 2 раза с задержкой 0.5 с; чтения при опросе не повторяются (берётся кешированное значение), а два таймаута подряд завершают опрос как offline |
| Адаптивные таймауты | 8 с чтение, 10 с запись, 15 с команды питания |
| Грациозная деградация | При ошибке чтения используется последнее кешированное значение |
| Оптимистичные обновления | UI обновляется мгновенно и держит записанное значение до следующего планового опроса, который его перечитывает (опрос через ~1 с после команды подхватывает её побочные эффекты, например декодер после смены входа); значения, заданные в standby, кешируются, поэтому опрос в режиме ожидания их не откатывает |
| **Опрос с учётом standby** | Сначала проверяется состояние питания; первый опрос после настройки один раз читает всё, даже в standby — дальше в режиме ожидания 1 запрос вместо ~40, кешированные значения сохраняются, интервал опроса снижается до 60 с. Настройки остаются **доступными и управляемыми** в standby — устройство применяет записи, а интеграция их запоминает |

| Режим работы, Тест колонок, Задержка проводного/беспроводного саба, Задержка surround | Sensor (x5, только чтение) | Диагностика |

**Всего: 41 сущность** (1 медиаплеер + 6 select + 13 number + 10 switch + 11 sensor)

## Решение проблем

| Проблема | Решение |
|----------|---------|
| Не подключается | Проверьте, что саундбар в той же сети. Попробуйте: `http://<IP>/api/getData?path=player:volume&roles=value` |
| Сущности недоступны | Приложение Klipsch может опрашивать одновременно — закройте его |
| Медленные обновления | Увеличьте интервал опроса в Настройках интеграции |
| Не работают команды кроме громкости/mute | Проверьте диагностический сенсор **MAC для подписи**. Если MAC не определён (или определён неверно), укажите MAC саундбара в поле **MAC устройства** в опциях |
| Интеграция не загружается | Проверьте логи HA на ошибки импорта. Нужен HA 2024.11+ |
| Логотип не виден в тёмной теме | Обновитесь до v2.5.19+ и перезапустите HA. Иконка для тёмной темы входит в интеграцию и работает с HA 2026.3+; на более старых версиях HA остаётся чёрная иконка с сайта значков HA |

## Известные ограничения

- Один саундбар на запись интеграции (для нескольких — добавляйте отдельно)
- Нет управления мультирумом / группами беспроводных колонок (используйте Klipsch Connect Plus)
- Управление идёт только через нативный HTTP API, без протоколов Cast и AirPlay. Google Cast доступен как вход (воспроизведение запускается из Cast-приложения); AirPlay нет в списке входов устройства, поэтому как источник он не предлагается (трансляция на саундбар с Apple-устройства от этого не зависит)
- Первоначальную настройку нужно **полностью** пройти в официальном приложении Klipsch Connect Plus — весь онбординг хотя бы один раз (именно это создаёт учётные данные для записи на прошивке 2026 года)

## Безопасность

Политика безопасности и рекомендации — в [SECURITY.md](../SECURITY.md).

**Замечание о сетевой безопасности:** саундбар работает по обычному HTTP, и его локальный API в LAN фактически без аутентификации. Старые прошивки не требовали аутентификации вообще; прошивка 2026 (`1.1.3.x`) подписывает большинство команд записи (`HMAC_SHA256_AES256`), но это **не реальная защита** — учётные данные выводятся из MAC самого устройства (который оно отдаёт без аутентификации) плюс зашитой во всю линейку константы, поэтому любой хост в сети может подделать подпись. Чтение всегда открыто. **Держите саундбар в доверенном / изолированном сегменте сети.** Полный разбор — в [отчёте по безопасности](SECURITY_ASSESSMENT_CORE_300.md) (раздел 12).

Все тесты выполняются на машине мейнтейнера, а не на GitHub. Первые пять бейджей показывают результаты этого подписанного локального прогона для последнего коммита в `main`. GitHub записывает их только после того, как проверит подписанные данные. *Verify signed local CI* — это и есть проверка на GitHub. *HACS validation* — проверка репозитория самим HACS, она выполняется на GitHub.

Данные можно проверить самостоятельно (Python 3.11 или новее, git, OpenSSH):

```bash
curl -fsSLO https://raw.githubusercontent.com/ilia-ae/klipsch_flexus/ci-results/allowed_signers
git clone https://github.com/ilia-ae/klipsch_flexus.git && cd klipsch_flexus
git fetch origin refs/notes/local-ci:refs/notes/local-ci
python3 -I scripts/verify_local_ci.py --sha "$(git rev-parse HEAD)" --allowed-signers-file ../allowed_signers
```

В `allowed_signers` лежит публичный ключ подписи мейнтейнера. Сравните его с SSH-ключами подписи, которые GitHub показывает для мейнтейнера: `curl -s https://api.github.com/users/ilia-ae/ssh_signing_keys`. Подробности — в [TESTING.md](TESTING.md#test-result-badges) (на английском).
